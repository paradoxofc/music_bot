====================================================================
           КРАТКАЯ МЕТОДИЧКА ПО КОМАНДАМ DOCKER ДЛЯ MUSIC BOT
====================================================================

В проекте настроено 3 сценария запуска:
 1. Локально / Разработка (docker-compose.yml) — монтирует код в контейнер.
 2. Продакшн на одном сервере (docker-compose.prod.yml) — всё в одном.
 3. Продакшн на двух серверах (bot + data раздельно).

--------------------------------------------------------------------
0. ПОДГОТОВКА (ПЕРЕД ПЕРВЫМ ЗАПУСКОМ)
--------------------------------------------------------------------
cp .env.example .env
# Заполните в .env токен бота, данные БД, Redis и API ключи


--------------------------------------------------------------------
1. ЛОКАЛЬНЫЙ ЗАПУСК / РАЗРАБОТКА (docker-compose.yml)
--------------------------------------------------------------------
# Собрать образ и запустить все сервисы (бот + postgres + redis) в фоне:
docker compose up -d --build

# Смотреть логи бота в реальном времени:
docker compose logs -f bot

# Проверить статус контейнеров (Up / healthy):
docker compose ps

# Перезапустить только бота (после правок кода, если не перезапустился сам):
docker compose restart bot

# Остановить все контейнеры проекта:
docker compose down

# Остановить и удалить volume с базой (СБРОС ДАННЫХ БД):
docker compose down -v


--------------------------------------------------------------------
2. ПРОДАКШН: ВСЁ НА ОДНОМ СЕРВЕРЕ (docker-compose.prod.yml)
--------------------------------------------------------------------
# Сборка и запуск:
docker compose -f docker-compose.prod.yml up -d --build

# Логи бота:
docker compose -f docker-compose.prod.yml logs -f bot

# Остановка:
docker compose -f docker-compose.prod.yml down

# Перезапуск бота:
docker compose -f docker-compose.prod.yml restart bot


--------------------------------------------------------------------
3. ПРОДАКШН: РАЗДЕЛЬНЫЙ ДЕПЛОЙ (2 СЕРВЕРА)
--------------------------------------------------------------------
А) На сервере БАЗЫ ДАННЫХ (Postgres + Redis):
docker compose -f docker-compose.prod.data.yml up -d
docker compose -f docker-compose.prod.data.yml logs -f

Б) На сервере БОТА (только Telegram-бот):
docker compose -f docker-compose.prod.bot.yml up -d --build
docker compose -f docker-compose.prod.bot.yml logs -f bot


--------------------------------------------------------------------
4. АВТОДЕПЛОЙ ЧЕРЕЗ СКРИПТ (deploy.sh)
--------------------------------------------------------------------
# На сервере сам подтянет git pull и перезапустит нужные контейнеры:
bash deploy.sh full    # для запуска всего на одном сервере
bash deploy.sh bot     # только бот
bash deploy.sh data    # только БД + Redis


--------------------------------------------------------------------
5. ПОЛЕЗНЫЕ СЕРВИСНЫЕ КОМАНДЫ
--------------------------------------------------------------------
# Войти в терминал работающего контейнера с ботом:
docker compose exec bot bash

# Выполнить импорт старых пользователей (из Makefile):
docker compose exec bot make import-users

# Запустить тесты в docker:
docker compose -f docker-compose.test.yml up --build --abort-on-container-exit
